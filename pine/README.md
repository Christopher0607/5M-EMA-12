# TradingView 脚本 · 安装与自动化接入

`nq_ema12_open.pine` — Pine v6 策略脚本，完整复现 `scripts/run_backtest.py` 的逻辑。

---

## 1. 图表设置（顺序不能错）

| 项目 | 值 | 为什么重要 |
|---|---|---|
| 品种 | `MNQ1!`（微型）或 `NQ1!` | 回测按 MNQ 规格（$2/点）；用 NQ 要把「点值」改成 20 |
| 周期 | **5 分钟** | 信号定义就是 5 分钟 K 线 |
| **盘前盘后** | **必须开启** | ⚠ 见下 |
| 时区 | 任意 | 脚本内部用 `America/New_York` 定位，不依赖图表时区 |

### ⚠ 「盘前盘后」是唯一会静默出错的设置

EMA12 跑在 **24 小时连续盘**上。如果关闭盘前盘后，TradingView 只用 RTH 的 K 线算 EMA，
09:35 那根线的 EMA 值完全不同，**信号会不一样，而且不会报错**。

脚本会自己检测这个情况：它检查 09:30 那根 K 线之前一根是不是 09:25。如果不是（说明中间断
了一整夜），会在图上打一个红色警告标签，右上角状态表也会显示「盘前盘后 ⚠ 未开启」。

打开方式：图表右键 → 设置 → 交易时段 → **取消勾选**「仅常规交易时段」。

## 2. 参数

### 止损方式（默认「价格百分比 0.5%」）

| 选项 | 设置 | 对应回测配置 | 生涯净到手 |
|---|---|---|---|
| **价格百分比 = 0.5** | 默认 | `pct 0.5% 固定止损` | **$58,176**（最高） |
| 价格百分比 = 0.75 | | `pct 0.75% 固定止损` | $36,934 |
| 固定点数 = 125 | 配合「固定手数 = 2」 | `fixed N=2` | $22,672（通过率 54%） |
| 固定点数 = 250 | 配合「固定手数 = 1」 | `fixed N=1` | $17,481（通过率 60%，存活率最高） |

**止损不会移动。** 回测里移动止损在 4 个配置 × 2 种路径假设 = 8/8 全部垫底。

### 手数上限（按你的账户填）

| 平台 | $50K | $100K | $150K |
|---|---|---|---|
| **TopStep** | 50 | 100 | **150** ← 脚本默认 |
| Lucid | 40 | 60 | 100 |
| Apex | 100 | 140 | 170 |
| Take Profit Trader | 20 | 40 | 50 |

脚本默认 150（TopStep $150K）。**买了别的档位就要改**，填错第一单就违规。

### 其他

- **每笔风险 $500** = $50K 账户的 1%。手数 = `floor(500 ÷ (止损点数 × 点值))`。
- **最大持仓 6 小时** → 15:35 ET 平仓。永远在收盘前，无隔夜跳空。
- **没有止盈**。这是回测里验证过的设计，不是漏了。时间出场用绿色方块和「15:35 平仓」标签单独标出，
  不会和止损混淆。

## 3. 图上会看到什么

- **黄色底纹** = 09:30–09:35 的信号 K 线
- **三角箭头** = 做多（蓝，向上）/ 做空（橙，向下）
- **标签** = 方向、手数、止损点数、本笔风险金额
- **红色横线** = 止损价，从入场画到出场
- **淡色底纹** = 持仓中的时间窗口
- **绿色方块 + 「15:35 平仓」** = 时间出场（不是止损）
- **灰色叉** = 信号出现但止损太宽、算出来 0 手，跳过。看到它说明风险预算撑不住当前波动
- **右上角表格** = 当前状态、止损距离、手数、风险金额、盘前盘后是否开启

## 4. 验证脚本是否和回测一致

```bash
./.venv/bin/python scripts/export_tv_check.py --since 2025 --max-contracts 150
```

生成 `results/tv_expected_trades.csv`，逐日列出方向、入场、止损点数、手数、出场原因。

**对照方法**：TradingView 策略测试器 → 成交列表 → 逐日核对**日期和方向**。

**不要期待价格完全一致。** 两边必然有差异：

| 差异来源 | 说明 |
|---|---|
| 数据源 | TradingView 的连续合约 ≠ Databento 的 `NQ.v.0` |
| 成交假设 | Pine 的 K 线内止损成交约定 ≠ 我用的「先到不利端」 |
| 成本模型 | 手续费和滑点算法不同 |

**必须一致的是信号集合**——同样的日子、同样的方向。方向对不上 = 图表设置错了，
99% 是盘前盘后没开。成交价差几个跳是正常的。

参考量级：2025 年至今 415 笔，方向分布 215 空 / 200 多，出场 225 时间 / 187 止损 / 3 收盘。

## 5. 自动化接入

### 政策（2026 年，务必自己再确认一次）

| 平台 | 考试阶段 | 资金账户 | 结论 |
|---|---|---|---|
| **Lucid** | ✅ | ✅ | **首选**：明文允许，原生支持 TradingView |
| **TopStep** | ✅ | ✅ | 备选：TopstepX / ProjectX 官方 API |
| Apex | ✅ | ❌ | 资金账户禁止全自动 bot，只能半自动 |
| Take Profit Trader | ❌ | ❌ | 明文禁止 |

三家都禁止 HFT / 延迟套利。这个策略一天一笔，不沾边。

### Webhook 消息格式（2026-08-29 照官方文档核实）

**两家的字段完全不同，不能混用。** 脚本里用「执行桥接商」参数切换，别手改 JSON。

#### TradersPost（Lucid 用这个）

来源：TradersPost 官方 `webhook-spec.json`。

```json
{"ticker":"MNQ1!","action":"buy","sentiment":"bullish","quantity":2,
 "stopLoss":{"type":"stop","stopPrice":21160.25}}
```
```json
{"ticker":"MNQ1!","action":"exit","sentiment":"flat"}
```

| 字段 | 说明 |
|---|---|
| `ticker` | 必填 |
| `action` | 必填，枚举：`buy` / `sell` / `exit` / `cancel` / `add` |
| `sentiment` | 枚举：**`bullish` / `bearish` / `flat`**——不是 `long`/`short` |
| `quantity` | 省略则默认 1 |
| `stopLoss` | **嵌套对象**：`{"type":"stop","stopPrice":N}`，`type` 可选 `stop`/`stop_limit`/`trailing_stop` |

> ⚠ **止损必须是嵌套对象。** 早先版本的脚本发的是扁平的 `"stop": N`——TradersPost 会
> **直接忽略**这个字段，仓位就没有止损保护了。已修正。

#### PickMyTrade（TopStep 用这个）

来源：PickMyTrade 官方 JSON alert 配置文档。

```json
{"symbol":"MNQ","data":"buy","quantity":2,"sl":21160.25,
 "token":"<你的token>","account_id":"<你的账户>"}
```
```json
{"symbol":"MNQ","data":"close","token":"<你的token>","account_id":"<你的账户>"}
```

| 字段 | 说明 |
|---|---|
| `symbol` | 根代码（`MNQ`），不是 `MNQ1!` |
| `data` | 枚举：`buy` / `sell` / `close` |
| `sl` | 直接给价格（也支持 `dollar_sl` / `percentage_sl`） |
| `token` / `account_id` | **凭证** |

> ⚠ **token 是凭证。** 填进脚本参数后，**必须把 TradingView 脚本设为 Private**——公开脚本
> 会暴露 inputs。PickMyTrade 官方也建议直接用他们后台生成的 JSON，而不是手写。

### 安全阀（脚本内置）

| 参数 | 默认 | 作用 |
|---|---|---|
| **Arm live orders** | **关闭** | 关闭时照常回测画图，但**不发入场 alert**。默认就是关的 |
| Limit to a date window | 关闭 | 限定生效日期，防止图表开着忘了关 |
| Stop after N consecutive losing days | 0（关） | 连亏 N 天后停止发单。平台的回撤规则会结束账户，这个先结束订单 |
| 重复入场防护 | always on | 已有持仓时拒绝再次入场，挡掉桥接商重复投递 |

> **完整的落地步骤看 [`connect_topstep.md`](connect_topstep.md)**（TopStep）
> 或 [`connect.md`](connect.md)（Lucid）。下面只是提要。

### TopStep（脚本默认走这条）

1. PickMyTrade 注册 → 连接 TopStep 账户 → **先选模拟账户**
2. TradingView 加载脚本 → 参数：执行桥接商 = `PickMyTrade`，Alert symbol = **`MNQ`**
   （根代码，不是 `MNQ1!`），手数上限 = 150（$150K 档）
3. 创建警报 → 条件选**策略本身**（不是单个信号）
4. Webhook URL 填 PickMyTrade 给的地址
5. 消息填 `{{strategy.order.alert_message}}` — 脚本已经按上面的 schema 拼好了
6. 走完 `paper_check.md` 全部清单，再打开 `Arm live orders`

> **档位选 $150K，不是 $50K。** TopStep 的一致性规则按利润目标缩放，$50K 的单日
> 盈利上限只有 $1,500，这个策略的盈利太集中，经常一天就撞线。$150K 净到手是
> $50K 的 14.8 倍。**这和 Lucid 的建议正好相反**，原因见 `connect_topstep.md`。

### Lucid（备选）

同上，桥接商参数改成 `TradersPost`，Alert symbol 改成 `MNQ1!`，手数上限改成 40。
Lucid 走 $50K 档——**它的规则和 TopStep 是反的**，别把两边的档位建议搞混。

### 上线前必做

1. **先跑模拟盘**，至少 2 周，核对每一笔和 `tv_expected_trades.csv` 对得上
2. **手数上限按账户填对**，填错会直接违规
3. **确认桥接商能下止损单**——策略靠固定止损保护，桥接如果只传市价单，风控就没了
4. **想跑多账户**：每个账户单独设手数，不要用一个信号无脑复制。回测显示复制账户完全正相关，
   一个爆全部爆
